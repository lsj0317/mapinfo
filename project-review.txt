================================================================================
                    MAPINFO 프로젝트 리뷰 - 개선 및 추가 개발 사항
================================================================================

프로젝트 개요: 태양광 패널 영업 지원 모바일 앱
기술 스택: React Native + Expo + TypeScript + Supabase
주요 기능: 지도 기반 건물 탐색, 등기부 열람, 영업 상태 관리

================================================================================
1. 구조적 개선 (Architecture)
================================================================================

[App.tsx 모듈화 - 최우선]

현재 문제:
  - App.tsx가 약 303KB로 모든 로직이 하나의 파일에 집중되어 있음

개선 방안:
  - screens/    : 화면별 컴포넌트 분리 (MapScreen, RegistryScreen, PropertyDetailScreen 등)
  - components/ : 재사용 UI 컴포넌트 (MarkerPin, StatusBadge, SearchBar 등)
  - hooks/      : 커스텀 훅 분리 (useRegistryLookup, useVWorldAPI, useBuildingSearch 등)
  - services/   : API 호출 로직 분리 (tilkoService, vworldService, supabaseService)
  - stores/     : Zustand 스토어 분리
  - utils/      : 유틸리티 함수 (haversine 계산, 암호화 등)
  - constants/  : 색상, 상태값, API URL 등 상수 정의

[네비게이션 도입]

  - 현재 단일 화면 구조로 보이며, React Navigation 도입으로 화면 전환 관리 필요
  - Stack Navigator, Tab Navigator를 활용한 체계적인 화면 구성

2. 코드 품질 (Code Quality)
================================================================================

[타입 안전성 강화]
  - any 타입 사용 부분을 구체적인 타입/인터페이스로 교체

[에러 처리 체계화]
  - 전역 에러 바운더리(Error Boundary) 추가
  - API 호출 실패 시 사용자 친화적 에러 메시지 표시
  - 네트워크 상태 감지 및 오프라인 모드 전환 UI

[테스트 강화]
  - 현재 __tests__/App.test.tsx에 기본 스모크 테스트만 존재
  - 단위 테스트: 유틸리티 함수, Zustand 스토어 로직
  - 통합 테스트: API 서비스 레이어
  - 컴포넌트 테스트: React Native Testing Library 도입
  - .mjs 테스트 파일들을 Jest 테스트로 통합

3. 보안 (Security)
================================================================================

[API 키 관리]
  - .env 파일에 민감한 정보(IROS 비밀번호, eMoney 인증정보 등)가 직접 저장됨
  - 민감 API 호출(Tilko 등기 열람)은 백엔드 서버(Supabase Edge Functions)를
    통해 프록시하는 것을 권장
  - 클라이언트에 암호화 키가 노출되는 구조 개선 필요

[Row Level Security (RLS)]
  - 현재 Supabase 스키마에서 RLS가 비활성화 상태
  - 사용자 인증 도입 시 RLS 정책 설정 필수
